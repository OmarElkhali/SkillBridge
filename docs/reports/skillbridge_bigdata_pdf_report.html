SkillBridge: Architecture, pipeline Big Data et fonctionnement par use case

Ce document explique le travail de chaque partie Big Data, le role de chaque conteneur Docker, l'installation des donnees, la liaison avec l'application web et le comportement du pipeline quand l'utilisateur clique sur Generate recommendations.

Regle d'architecture: le frontend React appelle seulement Spring Boot. Supabase reste la base applicative officielle. Hadoop, Hive, Flume, MapReduce et HBase restent terminal-first pour la demonstration Big Data.

1. Resume du projet

SkillBridge transforme une idee de projet en parcours d'apprentissage. L'utilisateur decrit ce qu'il veut construire. Le backend detecte les competences, classe les categories techniques et recommande des cours depuis un grand catalogue importe par le pipeline Big Data.

Figure 1 - Vue generale projet

Objectifs fonctionnels

  • Authentifier l'utilisateur avec email/password, Google ou GitHub.
  • Permettre la recherche dans un catalogue de cours volumineux.
  • Generer des recommandations explicables a partir d'une idee de projet.
  • Sauvegarder des cours et suivre la progression.
  • Donner a l'admin une vue catalogue, utilisateurs, pipeline et analytics.

2. Architecture technique complete

Figure 2 - Architecture applicative et Big Data

Le backend n'execute pas directement les jobs Hadoop pendant une requete utilisateur. Il ecrit des evenements et lit les rapports produits par le pipeline. Cette separation rend l'application web rapide et garde la partie Big Data demonstrable en terminal.

6. Use case: Generate recommendations depuis le web

C'est le use case le plus important. L'utilisateur est dans la page detail d'un projet et clique sur Generate recommendations. Le pipeline web rapide s'execute dans Spring Boot, puis un evenement est ecrit pour le pipeline Big Data.

Figure 6 - Generate recommendations web + Big Data

Details metier

  • Le backend verifie que le projet appartient a l'utilisateur connecte.
  • Le texte est normalise: minuscules, suppression ponctuation, tokens utiles.
  • Les skills sont detectes par correspondance avec la table skills.
  • Les cours candidats sont charges depuis courses et course_skills.
  • Le score combine titre, skills, categorie et bonus popularite/Big Data.
  • Le resultat est sauvegarde dans recommendation_snapshots et recommendation_results.
  • L'evenement PROJECT_RECOMMENDATION part dans events.log, puis Flume/HDFS.

7. Autres use cases et liaison Big Data

Recherche de cours

GET /api/courses?q=... lit le catalogue et ecrit COURSE_SEARCH si une recherche existe.

Flume envoie cet evenement dans HDFS. MapReduce calcule les top mots cles.

Clic sur un cours

POST /api/courses/{id}/click ecrit COURSE_CLICK.

Les stats de clics peuvent alimenter Hive et HBase.

Sauvegarder un cours

POST /api/saved-courses/{courseId} remplit saved_courses.

Sqoop importe cette table vers HDFS; Hive calcule les cours les plus sauvegardes.

Progression

PUT /api/progress/{courseId} remplit course_progress.

Hive/HBase construisent activity:avg_progress dans course_stats.

9. Conclusion

La partie Big Data de SkillBridge n'est pas seulement un ensemble de conteneurs: elle complete l'application web. Le catalogue massif est construit par Python, publie dans Supabase pour l'application, copie dans un PostgreSQL mirror pour Sqoop, stocke dans HDFS, analyse avec Hive et MapReduce, puis resume dans HBase et des fichiers JSON.

Quand l'utilisateur genere des recommandations, le backend donne une reponse rapide et explicable, puis laisse une trace evenementielle. Cette trace peut etre ingeree par Flume, analysee dans HDFS, et reutilisee dans les tableaux de bord admin. C'est la separation essentielle: le web reste rapide, le Big Data reste demonstrable, et les deux sont relies par les donnees.
